진행판 입력 가이드

진행판은 잠긴 틀과 두 입력 파일(서식 엑셀, dashboard.json)로 나뉘어 있습니다. 회신이 오면 입력 파일만 고치고 push하면 계산과 대시보드가 자동으로 바뀝니다. 화면 파일을 손대지 않으므로 서식과 기존 내역이 바뀌지 않습니다. 진행판으로 돌아가기

저장소 구성

GitHub 저장소에 올라가 있으며, push할 때마다 GitHub Actions가 계산과 대시보드 생성을 자동으로 합니다.

입력 · 고침

data/workbook.xlsx

자료요청 서식 엑셀. 회신값은 빈칸·파란 글씨 칸에, 가정은 원단위계산의 노란 칸에만 넣습니다.

입력 · 고침

data/dashboard.json

요청 13건의 상태·비고·진행 중, 흐름도·비용 나무 문구, 자료 검토, 판 정보, 수기값(단속 인원·암수율).

잠금

locked/ · config/ · pipeline/

대시보드 틀, 이 가이드, 서식 고정 칸 목록, 값↔셀 연결표, 파이프라인. 해시가 기록돼 있어 바뀌면 자동 계산이 멈춥니다.

결과 · 자동 생성

dist/

index.html(대시보드), data.json, guide.html, workbook.xlsx(재계산용 산식 포함), report.md(갱신 보고). 손으로 고치지 않습니다.

갱신 순서

사람이 하는 일은 1~3번뿐입니다. 4번부터는 자동입니다.

  1. 회신값을 엑셀에 넣기. data/workbook.xlsx의 해당 서식 칸(빈칸 또는 파란 글씨 칸)에 입력합니다. 제목·항목명·KEY·산식 칸은 잠겨 있어 바꾸면 갱신이 멈춥니다.
  2. 상태 고치기. data/dashboard.json의 requests에서 해당 건의 status, pill, got, received, missing, doing을 고치고, meta.asof와 meta.version을 올리고 meta.history에 한 줄을 더합니다.
  3. push. 두 파일을 커밋해 main에 올립니다. 검토를 받으려면 pull request로 올리면 점검만 돌고 결과는 저장하지 않습니다.
  4. 자동: 잠금 점검. 잠금 파일 해시와 서식 고정 칸을 확인합니다. 어긋나면 어느 칸이 바뀌었는지 보여 주고 멈춥니다.
  5. 자동: 재계산. 요청표 진행 상태와 「취합현황」 시트를 dashboard.json으로 다시 만들고, LibreOffice로 원단위계산을 재계산합니다.
  6. 자동: 점검과 생성. 산식 관계 31건을 점검하고, 통과하면 dist/에 대시보드와 보고서를 씁니다. 바뀐 값과 고칠 문구(경고)는 Actions 실행 요약과 dist/report.md에 나옵니다.
  7. 대시보드 게시. dist/index.html을 Claude 진행판 링크에 다시 올립니다(Claude에게 "dist 기준으로 진행판 갱신"이라고 요청).

회신이 들어오면 자동으로 바뀌는 값: 서식9 2025 전체 이수·미이수 두 줄이 모두 채워지면 r0·r1·Δr이 논문값에서 회신값으로, 서식7 6번·12번이 채워지면 UC-10이, 별도요청 2번·3번이 채워지면 UC-12가 계산됩니다. 그 밖의 값은 연결된 서식 칸이 바뀌면 그대로 따라 바뀝니다.

상태값 기준

요청 자료의 status는 아래 다섯 가지만 씁니다. 새 상태를 만들면 점검 패널이 ✕를 표시합니다.

값화면판정 기준집계
완료완료요청 항목을 전부 받았거나, 못 받은 항목이 모델에 쓰이지 않음13건에 포함
부분부분요청 항목 중 하나 이상을 받았고 빠진 항목이 있음. 총액만 온 경우도 부분포함
미회신미회신요청 항목을 하나도 받지 못함. 요청하지 않은 참고값만 와도 미회신포함
문헌대체문헌 대체회신은 없지만 공개 문헌으로 임시값을 넣음. 회신이 오면 부분이나 완료로 바꿈포함
추가추가 반영요청하지 않았으나 받아서 쓰는 자료. counted는 false제외

원단위(units)의 status는 별도로 반영·가정·미반영·문헌대체 네 가지를 씁니다.

숫자 · values (자동)

숫자는 dashboard.json에 쓰지 않습니다. 파이프라인이 config/values_map.json의 연결표대로 재계산된 엑셀 셀에서 읽어 dist/data.json의 values에 넣습니다. 엑셀 밖 숫자 두 개(최근 단속 인원 arrest_drug, 암수율 lambda)만 dashboard.json의 manual_values에 적고, N*는 둘의 곱으로 자동 계산됩니다.

문구 속 숫자 자리표시

흐름도, 원단위 설명, 민감도 메모, 자료 검토의 문구에는 숫자를 직접 쓰지 않고 {키|형식}으로 씁니다. 값이 바뀌면 문구도 같이 바뀝니다.

형식결과예 (값)
man만 원 단위 반올림{dc|man} → 484만
man1만 원, 소수 한 자리{medpc|man1} → 8.0만
won / int원 / 정수{uc02|won} → 8,615원
eok억 원(100억 미만 소수 둘째 자리){pgbud|eok} → 59.99억
pct / pct0백분율 소수 한 자리 / 정수{dr|pct} → 19.2%
x2 / x3소수 둘째·셋째 자리{D|x3} → 0.897

없는 키를 쓰면 화면에 ⟨키?⟩가 나오고 점검 패널이 ✕를 표시합니다.

나머지 블록

  • meta: 제목, 기준일(asof), 판(version), 계산 원본 파일명, 출처 문장, 변경 이력(history).
  • units: 흐름도의 원단위 칸. id, 원가중심점(cc: IN·PG·TX·CU·OC·MT), status, pill, main(큰 숫자), desc(설명).
  • flow: 흐름도의 행 순서. 각 행이 가리키는 요청 id와 원단위 id, ④열의 산식 항(term).
  • sensitivity_notes, docs: 민감도 설명과 자료 검토 카드 문구.
  • sc_tree: 사회적 비용(SC) 구성 나무. 노드마다 label, sub(산식 설명), 말단만 status(반영·부분·미반영), 선택으로 value(자리표시 사용), pill(표지 문구), new(true면 신설 표시). 위 칸의 상태는 화면이 아래 칸에서 자동으로 모으므로 적지 않습니다. 3장 항목이 산출되면 해당 말단의 status와 value만 고칩니다.

하지 않는 일

  • locked/, config/, pipeline/, .github/ 아래 파일을 고치지 않습니다. 고치면 다음 실행이 "잠금 파일이 바뀌었습니다"로 멈춥니다.
  • 엑셀에서 시트를 추가·삭제하거나 이름·순서를 바꾸지 않습니다. 원단위계산 시트에는 파란 글씨·노란 칸 밖에 아무것도 쓰지 않습니다.
  • 「취합현황」 시트와 1.요청표의 진행 상태 칸은 고치지 않습니다. dashboard.json에서 자동으로 만들어집니다.
  • dist/의 파일을 손으로 고치지 않습니다. 다음 실행 때 덮어써집니다.
  • request의 id, values의 키, 상태값 이름을 바꾸지 않습니다.
  • 서식이나 대시보드 틀을 꼭 바꿔야 할 때만 python pipeline/relock.py --version 새판 --reason "이유"로 판을 올립니다. 이유는 locked/CHANGELOG.md에 남습니다.

요청 한 건의 예

{
 "id": "4", "name": "재활교육 운영실적", "form": "서식4", "owner": "마약사범재활팀",
 "core": true, "counted": true, "status": "부분", "pill": "이수만",
 "asked": 4, "got": 1, "replied": "2026-09-07", "cc": "PG",
 "received": "2024~2026.7 과정별 이수 인원(전국 합계)",
 "missing": "기수, 개시, 중도탈락 인원·사유, 기관별 구분",
 "model": "UC-07·UC-06 분모",
 "note": "개시·탈락이 없어 1인당 원가는 과대 쪽",
 "doing": "중도탈락 인원 재요청"
}

중도탈락 인원이 회신되면 got을 2로, missing에서 해당 문구를 빼고, doing을 ""로 바꾼 뒤 서식4 엑셀의 개시·탈락 칸에 값을 넣고 push합니다.
